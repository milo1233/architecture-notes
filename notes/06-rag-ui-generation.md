# 디자인 명세를 RAG 로 태워 UI 를 생성하기

**내부망 디자인 협업툴의 AI 고도화 PoC** · LangGraph, RAG, 디자인툴 플러그인, Node.js

### 문제

디자인 시스템 명세·개발 가이던스·레이아웃 규칙이 문서와 디자인 파일에 흩어져 있었습니다.
"이 규칙들을 데이터로 만들어서, 사용자 요청을 받아 규칙에 맞는 화면을 생성할 수 있는가"를
검증하는 과제였습니다.

핵심 난점은 **디자인 정보가 한 가지 형태가 아니라는 것**이었습니다.
컴포넌트는 생김새(이미지)이자 구조(트리)이자 용도(자연어)입니다. 어느 하나만으로는 부족합니다.

### 판단 — 멀티모달 청킹

한 컴포넌트를 **세 조각으로 나눠 담고, 메타데이터로 다시 이었습니다.**

| 조각 | 무엇 | 답할 수 있는 질문 |
|---|---|---|
| **Visual** | 캡처 이미지 | "이렇게 생긴 게 뭐지" |
| **Structural** | 디자인툴 트리 XML | "이건 어떻게 조립돼 있지" |
| **Semantic** | 자연어 설명 | "언제 쓰는 거지" |

셋을 따로 넣으면 검색 결과가 파편화됩니다. 그래서 **메타데이터를 연결고리로 두어**
한 조각이 걸리면 나머지를 같이 끌어오게 했습니다.

DB 도 **컴포넌트용과 UX 문서용으로 분리**했습니다. 성격이 다른 문서가 한 인덱스에 있으면
서로의 검색 품질을 갉아먹습니다. 대신 프롬프트에 **소스 우선순위 규칙**을 주입해
어느 쪽을 먼저 믿을지 정했습니다.

### 파이프라인

한 번에 화면을 만들라고 하지 않고, 결정을 단계로 쪼갰습니다.

```
요구사항 확장 → 섹션 레이아웃 결정 → 슬롯 후보 결정
   → 컴포넌트 확정 → 내부 레이아웃·variant 결정 → 렌더링
```

각 단계가 앞 단계의 결과만 받으므로, 어디서 틀렸는지 짚을 수 있습니다.

- **슬롯 후보 선정** — 슬롯 힌트와 컴포넌트 스냅샷으로 RAG 매칭, 유사도 0.6 이상만 통과
- **카탈로그 자동 생성** — 컴포넌트 메타데이터를 LLM 으로 만들고 스냅샷으로 관리.
  손으로 쓰면 컴포넌트가 늘 때마다 사람이 따라가야 합니다
- **렌더링 스펙 재설계** — 전체 트리를 통째로 넘기던 방식에서 변경분만 넘기는 배열 방식으로 전환.
  환경변수 분기로 기존 방식과 나란히 돌려 호환을 유지했습니다
- **유효성 필터** — 파싱에 실패하면 거기서 예외를 내고 멈춥니다.
  깨진 스펙이 렌더링까지 흘러가면 어디서 틀렸는지 못 찾습니다

인수인계 없이 넘겨받은 코드라, **코드를 역추적해 프롬프트·state·스키마를 복원**하고
슬롯 선정 노드 기준으로 파이프라인 정합성을 먼저 맞췄습니다.

### 검증 — 규칙을 바꿔서 결과가 따라오는지 본다

"결과물이 그럴듯한가"는 판정 기준이 못 됩니다. LLM 은 항상 그럴듯합니다.

그래서 **대조 실험**을 했습니다.

1. 제시된 컴포넌트와 레이아웃 규칙이 결과물에 반영되는지 확인
2. **기반 규칙을 의도적으로 바꾼 뒤** 다시 생성 → 바뀐 규칙이 결과에 나타나는지 확인

2번이 핵심입니다. 이게 되어야 모델이 **규칙을 실제로 읽고 따르는 것**이지,
그럴듯한 UI 를 외워서 뱉는 게 아니라는 근거가 됩니다.
