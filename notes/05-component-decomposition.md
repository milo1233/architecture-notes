# 1,960줄 컴포넌트를 무중단으로 해체

**조직 업무 가시화 플랫폼의 프론트엔드** · React(TypeScript), react-router, TanStack Query

### 문제

최상위 컴포넌트 한 파일이 **1,960줄**이었습니다.
렌더·상태·데이터 fetch·타입 정의가 전부 거기 있었습니다.

돌아가고는 있었지만, **어디를 건드려도 무엇이 깨질지 알 수 없는 상태**였습니다.
서비스는 이미 사내에서 쓰이고 있어서 멈출 수 없었습니다.

### 판단

한 번에 뜯으면 반드시 뭔가 깨집니다. 그리고 깨진 걸 모릅니다 — 비교할 기준이 없으니까요.

그래서 **분해보다 먼저 현행 동작을 테스트로 고정**했습니다.
지금 코드가 "옳은지"는 묻지 않고, "지금 이렇게 동작한다"만 박아둡니다.
그 뒤에 리팩터링해서 테스트가 그대로 통과하면, 동작이 안 바뀐 겁니다.

> **특성화 테스트(Characterization Test)** — Michael Feathers, *Working Effectively with Legacy Code*.
> 레거시를 "명세가 없는 코드"로 정의하고, 손대기 전에 현재 동작을 캡처해 안전망을 만드는 기법입니다.

그리고 **세 단계로 쪼개서** 한 번에 한 종류의 변화만 일으켰습니다.

### 1단계 — 순수 이동만

먼저 **동작을 전혀 바꾸지 않는 것만** 했습니다.

- 중복 유틸(응답 파싱·에러 메시지·날짜 포맷)을 공용 모듈로 추출
- 인증 화면·설정 모달·대시보드 뷰를 프레젠테이션 컴포넌트로 이동

옮길 때 규칙을 하나 뒀습니다 — **JSX 는 그것만 먹이는 state 와 함께 옮기고,
여러 곳이 쓰는 상태는 그대로 두고 props 로 내린다.**
욕심내서 상태까지 재설계하면 1단계가 아니라 전면 개편이 됩니다.

### 2단계 — 탭을 URL 로

`useState` 로 관리하던 화면 전환을 라우터 URL 로 올렸습니다.
새로고침과 딥링크가 되고, 화면 전환 상태가 최상위 컴포넌트에서 빠집니다.

인증 게이트는 **라우터 바깥의 전체 게이트로 유지**했습니다.
라우트마다 인증을 거는 구조로 바꾸면 그건 이동이 아니라 설계 변경입니다.

### 3단계 — 데이터 계층

매 마운트마다 직접 부르던 fetch 를 선언적 쿼리로 옮겼습니다.
여기서 가장 중요한 판단은 **라이브러리의 똑똑한 기본값을 일부러 껐다**는 것입니다.

```
retry: false                    재시도 안 함
refetchOnWindowFocus: false     창 포커스에 다시 안 부름
staleTime: 0                    캐시 신선도 판정 안 함
```

이 기본값들은 보통 켜는 게 좋습니다. 그런데 켜는 순간 **요청 타이밍이 달라집니다.**
리팩터링에서 동작이 달라지면 그건 리팩터링이 아니라 기능 변경입니다.
먼저 동작을 그대로 옮기고, 개선은 별도로 하는 게 맞다고 봤습니다.

폴링도 마찬가지로 **기존 주기를 테스트로 고정**하고 옮겼습니다
(요약 폴링 4000ms × 20회, 다른 하나 1500ms).

### 결과

**1,960줄 → 167줄 (−91%).** 배포 후 회귀 **0건.**

숫자보다 중요한 건 이제 **한 곳을 고칠 때 영향 범위를 말할 수 있다**는 점입니다.
