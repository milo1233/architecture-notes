# 설계 기록

웹과 AI 에이전트를 만들며 내렸던 판단들을, **무엇이 문제였고 왜 그렇게 결정했는지** 중심으로 적었습니다.
회사명·고객사명·시스템명은 모두 뺐고, 화면 캡처나 코드는 넣지 않았습니다.

**[1. 기능이 무한히 붙는 에이전트 베이스](notes/01-agent-base.md)**
확장을 코어 수정이 아니라 인터페이스 구현으로 흡수. 7주간 피쳐 49건을 코어 변경 3.4%로

**[2. 조용히 멈춘 큐 — 원인 셋, 그리고 틀렸던 복구 보고](notes/02-queue-failure.md)**
운영 DB 로 원인 셋을 가르고, 틀렸던 「자동 복구」 보고를 정정해 LLM 호출 0회로 되살림

**[3. 서로 엉킨 Manager 들을 Mediator 로 끊기](notes/03-mediator.md)**
port 만 노출해 순환참조 제거, 공통 베이스를 2개 프로젝트가 참조

**[4. 실시간 중계 플랫폼 1인 개발](notes/04-realtime-media.md)**
카메라·화면·오디오를 합친 통합 스트림 송출. 3개월 단독

**[5. 1,960줄 컴포넌트를 무중단으로 해체](notes/05-component-decomposition.md)**
특성화 테스트로 동작을 고정하고 3단계로 분해. 167줄, 회귀 0건

**[6. 디자인 명세를 RAG 로 태워 UI 를 생성하기](notes/06-rag-ui-generation.md)**
멀티모달 청킹. 규칙을 바꿔 결과가 따라오는지로 검증

**[7. 조직 암묵지를 LLM 이 참조하게 만들기](notes/07-knowledge-wiki.md)**
인용 0건의 원인을 편차에서 찾아 카탈로그 노출로 해결

**[8. 개선을 증명하려면 대조군을 먼저 얼려야 한다](notes/08-frozen-control.md)**
SHA-256 동결 가드, 같은 실행 안 0 대 8 — 좋아진 것·모르는 것·아닌 것을 가른 결론

**[9. 프롬프트가 스스로를 부정하고 있었다](notes/09-prompt-contradiction.md)**
성립 불가한 조건 제거, 억제 표현 46 → 12회

**[10. 입력 토큰의 87%가 이미지였다](notes/10-image-tokens.md)**

## 읽는 법

각 글은 독립적입니다. 관심 가는 것 하나만 열어도 됩니다.
형식은 모두 **문제 → 판단 → 행동 → 결과** 이고, 결과 수치는 이력서와 같습니다.

관측 체계를 먼저 만들고 그 데이터로 LLM 낭비를 줄인 과정은 [2번](notes/02-queue-failure.md)에 함께 적었습니다.
